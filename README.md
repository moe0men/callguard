# Yandex Call Guard

Android-приложение: смотрит незнакомый входящий номер через обычный поиск Яндекса. Если в выдаче есть метка спама или мошенничества, звонок остаётся, но становится беззвучным. Если меток нет, капча или таймаут — обычный звонок. Номера из контактов не проверяются.

Без баз номеров, без API-ключей, без аккаунта. Только мгновенный поиск в интернете.

## Как работает

1. Приложение получает роль `ROLE_CALL_SCREENING` (`CallScreeningService`). Android будит его до звонка.
2. Номер в контактах → сразу обычный звонок.
3. Номера нет → невидимый `WebView` (движок Chromium) открывает `https://yandex.ru/search/?text=<номер>`.
4. `document.body.innerText` чистится, ищутся метки рядом с номером (окно 600 символов): «нежелательный звонок», «есть жалобы», «подозрение на мошенничество», «спам», «предложение товаров или услуг», «не берите трубку».
5. Метка найдена → `CallResponse.Builder().setSilenceCall(true)`. Звонок не блокируется, только без звука.
6. Нет метки / капча / ошибка / таймаут → обычный звонок.

Почему WebView, а не HTTP-клиент: Яндекс режет обычные запросы SmartCaptcha, потому что у них нет JavaScript и не браузерный отпечаток TLS. Реальный Chromium проходит проверку и получает обычную выдачу. Проверено: один и тот же IP, HTTP → `showcaptcha`, Chromium → нормальная выдача.

Дедлайн на проверку 4.3 с: Android ждёт ответ `respondToCall` не больше 5 секунд, после чего звонок не начнёт звонить вовремя.

Кэш результатов только в памяти процесса: спам и «чисто» — 6 часов, «нет данных» — 15 минут. На диск ничего не пишется.

## Установка

1. Открыть https://github.com/moe0men/yandex-call-guard/releases и скачать `app-debug.apk` из последнего релиза.
2. Поставить APK на телефон (разрешить установку из неизвестных источников).
3. Открыть приложение, нажать «Дать роль определителя номера», затем «Разрешить доступ к контактам».
4. Проверить вручную: ввести номер, «Проверить сейчас», смотреть журнал.

Каждый пуш в `main` собирает APK и публикует его в Releases автоматически. Артефакт `yandex-call-guard-debug` в Actions остаётся как резерв.

## Сборка локально

Нужен JDK 17 и Android SDK (compileSdk 36).

```bash
./gradlew assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Ограничения

- WebView может отдать SmartCaptcha, если Яндекс уже пометил устройство. Тогда вердикт `UNKNOWN` и обычный звонок.
- Яндекс может менять разметку выдачи — тогда метки перестанут находиться.
- Проверка должна уложиться в ~4.3 секунды, включая инициализацию WebView. На медленном мобильном интернете не успеет.
- Некоторые прошивки (Xiaomi, Samsung, Huawei) ограничивают фоновые сервисы. Может понадобиться автозапуск и отключение оптимизации батареи.
- Публикация в Google Play с таким поведением невозможна: политика запрещает перехват звонков сторонними приложениями. Sideload и F-Droid — рабочий вариант.
- Запросы идут на серверы Яндекса, номер туда передаётся. Это не приватная проверка.

## Отказ от ответственности

Проект не связан с Яндексом. Использует публичную поисковую выдачу, что нарушает пользовательское соглашение Яндекса. Решение о звонке всегда консервативное: при любой неопределённости звонок остаётся обычным.

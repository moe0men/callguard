# Yandex Call Guard

Android-приложение: проверяет незнакомый входящий номер через сервис определителя номера Яндекса. Если номер помечен как спам, мошенничество или телемаркетинг, звонок остаётся, но становится беззвучным. Если меток нет, ошибка или таймаут — обычный звонок. Номера из контактов не проверяются.

Без локальных баз, без API-ключей, без аккаунта.

## Как работает

1. Приложение получает роль `ROLE_CALL_SCREENING` (`CallScreeningService`). Android будит его до звонка.
2. Номер в контактах → сразу обычный звонок.
3. Номера нет → запрос:

```
GET https://cid.yandex.net/v7/info?phonenums=79001234567&verticals=ugc&lang=ru&lr=213
Authorization: Bearer android
```

4. Ответ разбирается по полям `ugc.verdict`, `ugc.polarity`, `ugc.description`, `geo.results[0].name`:

| Ответ Яндекса | Вердикт | Поведение |
|---|---|---|
| `polarity: "negative"` или `verdict` содержит `telemarketing`, `spam`, `fraud`, `debt`, `collect`, `advert`, `promo` | `SPAM` | `setSilenceCall(true)` |
| `polarity: "positive"` или `notification`, `bank.notification`, `taxi`, `telecom` | `CLEAN` | обычный звонок |
| `verdict: null`, нет `ugc` | `UNKNOWN` | обычный звонок |

5. Ответ приходит за 70–150 мс, дедлайн 2.5 с. Android ждёт `respondToCall` не больше 5 с.

Кэш вердиктов только в памяти процесса: спам и «чисто» — 6 часов, «нет данных» — 15 минут. На диск ничего не пишется.

## Что это за API

Это тот же сервис `cid.yandex.net`, к которому обращается АОН Яндекс.Браузера и приложения «Яндекс». Публичной документации нет. Заголовок `Authorization` обязателен: без него сервис отвечает `400 {"message":"error"}`, и сейчас его значение не проверяется. Яндекс может включить проверку подписи в любой момент.

Схему нашёл по репозиторию `LencoDigitexer/YandexCallerCheck_bot`: там тот же `cid.yandex.net/v7/info`, но запрос без заголовка `Authorization`, поэтому у него сейчас `400`.

## Установка

1. Открыть https://github.com/moe0men/yandex-call-guard/releases и скачать `app-debug.apk` из последнего релиза.
2. Поставить APK на телефон (разрешить установку из неизвестных источников).
3. Открыть приложение, нажать «Дать роль определителя номера», затем «Разрешить доступ к контактам».
4. Проверить вручную: ввести номер, «Проверить сейчас», смотреть журнал.

Каждый пуш в `main` собирает APK и публикует его в Releases автоматически.

## Сборка локально

Нужен JDK 17 и Android SDK (compileSdk 36).

```bash
./gradlew assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Ограничения

- Неофициальный API. Может измениться без предупреждения: версия `v7`, набор полей, требование подписи.
- Ложных срабатываний меньше, чем при парсинге поиска, но метка Яндекса — это отзывы пользователей, не приговор.
- Проверка должна уложиться в 2.5 с.
- Некоторые прошивки (Xiaomi, Samsung, Huawei) ограничивают фоновые сервисы. Может понадобиться автозапуск и отключение оптимизации батареи.
- Публикация в Google Play с таким поведением невозможна: политика запрещает перехват звонков сторонними приложениями. Sideload и F-Droid — рабочий вариант.
- Номер передаётся на серверы Яндекса. Это не приватная проверка.

## Отказ от ответственности

Проект не связан с Яндексом. Использует недокументированный внутренний API, что нарушает пользовательское соглашение Яндекса. Решение о звонке всегда консервативное: при любой неопределённости звонок остаётся обычным.
